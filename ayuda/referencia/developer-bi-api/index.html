    Developer — BI API

    Autor: luis · Revisado: 13-nov-2026

    The machine interface of FnF Analytics: a read-only HTTPS endpoint that feeds the external BI dashboards (Shiny). The dashboards live outside the app's server, and the database only listens on localhost, so instead of connecting by SQL they consume this endpoint. A public REST API is planned; today this BI feed is the only machine interface.

    Base URL: https://app.fnfanalytics.com/api/bi/

    Authentication

    There are no user accounts here — one token per dashboard, and each token sees only its company. You pass it in the Authorization header:

    Authorization: Bearer <token>
    Rule Detail
    Token store settings.BI_API_TOKENS, loaded from the server's environment (DJANGO_BI_API_TOKEN, DJANGO_BI_API_TOKENS as company:token,company:token).
    Scope A token is bound to one company id; every query filters by it. A token can never read another company's rows.
    Comparison Constant-time (hmac.compare_digest), and all tokens are compared — never early-exit — so response times don't leak which token you hit.
    No token, no access Without a valid token every endpoint answers 401 with {"detail": "No autorizado."}. There is no anonymous access.

    Endpoints

    Both endpoints are GET only (anything else is 405) and gzip-compressed when your client sends Accept-Encoding: gzip.

    Method Path Returns
    GET /api/bi/dataset/ All datasets the dashboard needs, in one call.
    GET /api/bi/servicios-externos/ The servicios_externos table only — feeds the dashboard's on-demand "Servicios externos" CSV download.

    Response format

    Column-oriented JSON: keys appear once and columns keep exactly the order the database returns them. This is contractual — the R side renames columns by position, so a reordered column is a silently broken dashboard.

    {
  "generated_at": "2026-11-13T10:15:02",
  "datasets": {
    "tareas": {
      "columns": ["id", "init_date", "..."],
      "types":   {"id": "number", "init_date": "date"},
      "nrow": 2610,
      "data":    {"id": [1, 2], "init_date": ["2021-01-04", "2021-01-05"]}
    }
  }
}

    Type labels you can get in types: bool, datetime, date, time, number, string — and null for a column with no non-null value yet. Values are JSON-native: datetimes as YYYY-MM-DD HH:MM:SS, dates as YYYY-MM-DD, times as HH:MM:SS, decimals as floats.

    Datasets

    Each dataset maps to one raw SQL query against the production tables. Every query filters by the token's company (%(company)s); the shared catalog of products and activities (actividades, precios_producto, productos through machinery consumptions) also includes company 1, the general company where common items are registered. tareas and mano_obra start at 2021-01-01; their _full variants have no date floor and exist so each consumer gets exactly what its SQL says.

    Dataset Source table(s) Notes
    tareas activities_task From 2021-01-01 on.
    mano_obra activities_partworker Workers on those tasks.
    tareas_full activities_task No date floor.
    mano_obra_full activities_partworker No date floor.
    mano_obra_trabajador activities_partworker_worker Worker rows of each labour entry.
    precios_mano_obra costs_workercost Rates of the company's workers.
    maquinaria activities_partmachinery Machinery lines of the tasks.
    maquinaria_maquina activities_partmachinery_machine Machine rows of each line.
    precios_maquinaria costs_machinerycost Rates of the company's machines.
    producto activities_partproduct Product lines of the tasks.
    precios_producto costs_productcost Own company and company 1 (shared catalog).
    servicio activities_externalservice External services of the tasks.
    actividades activities_activity Own company and company 1.
    fincas fields_farm The company's farms.
    subfamilias fields_family Shared catalog: whole table, no filter.
    cultivos fields_crop The company's crops.
    tareas_cultivos activities_task_crops Crops per task.
    maquinas machinery_machine id, name of the company's machines.
    mantenimientos machinery_maintenance Selected columns only.
    partes_mantenimiento machinery_maintenanceworker Workers on those maintenances.
    partes_mantenimiento_trabajador machinery_maintenanceworker_worker Worker rows of each.
    consumos machinery_consumption Fuel/product consumptions.
    productos warehouse_product Products that appear in consumptions.
    trabajadores contacts_worker id, name of the company's workers.

    servicios_externos (its own endpoint) joins tasks, activities, crops, farms, families and suppliers, grouped by task and ordered newest first.

    The dashboard link inside the app

    The AppBI model (users app) stores, per company, the name, link and description of each external dashboard. The «BI» menu entry in the app lists those links — it points at the Shiny app, which in turn authenticates to /api/bi/ with the company's token.
